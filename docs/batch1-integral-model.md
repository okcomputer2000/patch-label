# 第一批：字符与整数转换

本分支从 `1e91172`（e47ecff 加源码目录修复）开始。根因未修复、边界不完整、过度修复的分类函数及其质量检查、路径匹配函数保持不变。

## 已实现

- Java 字符常量：普通单个 UTF-16 单元、普通转义、合法八进制转义。`'0'` 是 48，`'\0'` 是 0；`'\400'` 不当作合法单字符处理。
- cast 明确读取 tree-sitter 的 `value` 和 `type` 字段，不再把 `(long) x` 的第一个子节点 `long` 当作被转换的值。
- 对由已知整数/字符常量组成的表达式，保留 Java 类型，正确执行扩大、缩位、符号解释及嵌套转换。
- 新字符/cast 所处的闭合整数运算遵守 Java 的数值提升、32/64 位溢出、除法向零取整及余数符号。比如 `(char)65535 * 65535` 是 -131071。
- 新字符/cast 的闭合比较使用同一整数规则；不会把 `0xffffffff` 错当作正的 4294967295。

路径与输出提取统一使用 `ExprResult`，保存值、Java 类型、正常条件、未支持原因及源码证据；原 `_java_expression` 裸表达式接口保留给兼容调用。新增 `ModelContext` 从完整源码取得参数和方法开头的唯一局部声明。

- 未被写入的 byte/short/char/int/long 参数可参与比较和整数转换。参数用固定位宽值表示，char 天然只取 0—65535，不另加可能被边界公式取反的范围条件。
- 局部变量只接方法开头连续声明区的唯一初始化；可使用常量、已支持参数、别名和整数 cast。被再次赋值、遮蔽、循环修改或来源不清楚时保留未知。
- 同一方法的补丁前后条件统一使用同一参数身份（完整方法签名与参数序号）；任一侧含字符/cast 时，两侧该方法的全部条件统一进入新接口，避免同一输入被错误拆成两个变量。签名无法对应时不确认。
- 在将新模型结果当作准确条件前，核对源码方法与 CFG 方法身份；无法核对时明确保留未知。这是拒绝错误对应，不改原路径选择规则。
- 输出片段按每个修改块前后两侧取并集启用新模型；缺完整参数上下文的动态输出继续未知，不影响不含字符/cast 的其它修改块。
- 修改块片段还缺真实返回/赋值接收类型；保存已算出的表达式数值和类型，但不据此确认输出等价。例如 `(byte)1` 和 `1` 返回到 Object 时分别得到 Byte 和 Integer，不能只因数值同为 1 就证明修改可删除。

## 明确保留的未知

第一批没有建立可变赋值、对象状态、函数返回、数组元素和浮点运算的完整模型。它们不能因为最终存在整数 cast 就被当成已理解的整数值。原始 Unicode 源码转义也暂不接收。

未通过类型/赋值检查的动态比较，以及尚未实现的动态算术，整体回退为未知表达式，并保留具体依赖说明。不能只加一条“未支持”备注，然后继续用可能错误的整数公式排除路径。例如：

- `char c` 不可能小于 `\0`，不能用允许负数的普通整数代替后声称精确。
- `double` 可能是 NaN，不能用整数三种大小关系把实际可执行情况判成无解。
- 两次同名函数调用可能返回不同值。新未知量按源码内容、语法位置和出现次数区分，不假定函数没有状态变化。

这些保护没有放宽三类确认规则，也不保证消除一题全部 `inconclusive`。Closure-38/51 的实际例子是 `double x` 转 `long`，本批修复读取位置后仍保留浮点转换限制。
